| Category | Question | Finding | Severity | Mitigation |
|---|---|---|---|---|
| Authn | Is every non-public endpoint protected by JWT? | All 7 endpoints have `security: bearerAuth` but there is no global security block — a new endpoint added later will be unprotected by default | M | Add a global `security: - bearerAuth: []` at the top level of the spec.|
| Authz | Does every /{id}-shaped endpoint check object ownership? | `PATCH /borrow-requests/{requestId}`,`GET /books/{bookId}/borrow-requests` , `POST /books/{bookId}/photos`and `PATCH /loans/{loanId}` has no ownership check - any member with a valid JWT can get book requests,upload an image, accept requests and mark loans as returned for a book they do not own/havent borrowed. | H |  Compare `request.book.ownerId` against the JWT `sub` claim - return 403 if they do not match. |
| Injection | Are all DB queries parameterised? | `GET /books` accepts a free-text `search` parameter. If the Node.js implementation concatenates this into a SQL string directly it is vulnerable to SQL injection | H | All queries must use parameterised statements with the value passed separately, never concatenated. |
| Secrets | Where are connection strings stored? | Risk of Azure SQL connection string, Redis password, or Blob Storage key being stored in a `.env` file committed to Git | H | All secrets go in Azure Key Vault. App Service reads them as environment variables at runtime via Key Vault references. Add `.env` to `.gitignore` and a pre-commit hook that scans for secrets |
| Transport | Is TLS enforced at Front Door? | App Service can still accept plain HTTP requests that bypass Front Door entirely, bypassing the WAF and rate limiting | M | Set `HTTPS Only = true` in App Service configuration. Add an access restriction so App Service only accepts traffic from the Azure Front Door service tag |
| Rate limit | Are auth and write endpoints rate-limited? | `POST /books/{bookId}/borrow-requests` and `POST /books` have no rate limit a bot could spam borrow requests or flood the catalogue with fake listings | M | Configure an Azure Front Door WAF rate limit rule: max 10 requests per minute per IP on all POST endpoints. Return `429 Too Many Requests` with `Retry-After: 60`. |
| PII | What PII appears in responses, logs, or queues? |The NFRs require authentication failures and loan events to be logged with memberId in Application Insights. Loan activity tied to a member ID constitutes behavioural PII - it reveals borrowing patterns of specific members. If the Application Insights workspace is not access-controlled, this telemetry could expose member behaviour to unauthorised viewers   | M | Restrict the Application Insights workspace to the operations team only |
